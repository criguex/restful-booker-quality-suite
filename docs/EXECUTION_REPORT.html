Confirmed defects

These are classified as defects because they violate measurable test oracles: HTTP status semantics, the declared media type, required-field validation, or preservation of accepted business data. The finding is therefore based on expected-versus-actual evidence rather than personal preference. The accompanying Detailed Defect Report contains an expanded rationale, business impact and executable curl reproduction for every RB item.

RB-001 XML response declares the wrong content type

  • Endpoint: GET /booking/:id
  • Request: Accept: application/xml
  • Expected: HTTP 200, XML body and an XML content type.
  • Actual: HTTP 200 and XML body with Content-Type: text/html; charset=utf-8.
  • Impact: Strict clients and schema middleware may reject or misparse the response.
  • Disposition: P1 compatibility defect; fix before XML is advertised as a supported public contract.

Behaviors to clarify with the product team

These remaining observations need confirmation of the intended public contract:

  • /ping returns 201 rather than the conventional 200.
  • An unsupported Accept value returns the non-standard HTTP 418 response.

Automation design

The framework uses Playwright, TypeScript and Zod. Each test owns uniquely named data and cleans it in finally; no scenario depends on seeded IDs or execution order. Functional, contract, component and performance checks are separate projects. CI starts a pinned Restful Booker revision in Docker, waits for health, executes static and dynamic gates, and retains reports and traces.

Deliberate exclusions

The live assessment is time-boxed. Load and soak testing, concurrency races, specialist security testing, dependency remediation, browser UI, third-party failure simulation and exhaustive date combinations were left outside the release gate. This keeps the work centered on booking and authorization risk without presenting the assessment as exhaustive coverage.
